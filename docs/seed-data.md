# Seed data

Generated by `uv run python scripts/gen_seed.py` (deterministic; a unit test fails if
`seed/` is out of date). All dates are relative to the mock clock: `@now`, `@now-29d`,
`@now+2.5d`. They resolve to ISO-8601 UTC on load or reset (SD-6).

| File | Contents |
|---|---|
| `catalog.json` | 33 products: sku, name, category, price (INR), `in_stock`. Categories include the non-returnable `perishable`, `personalised`, `hygiene`. |
| `customers.json` | 65 customers: id, name, `emails` (first is primary; some have several), phone, `tier` (`standard`/`vip`), address, `contact_history`. |
| `orders.json` | 170 orders: items (line_id, sku, category, qty, unit_price, returned_qty), subtotal, shipping_fee, total, payment method (card last4 only, masked UPI), timeline dates, carrier, tracking number, tracking events. |
| `payments.json` | `charges` (succeeded/failed, incl. duplicate captures and failed-then-retried) and payment `events`. |
| `returns.json` | Existing return authorisations (authorised / received / refunded). |
| `refunds.json` | Existing refunds (initiated / processed). |
| `scenarios.json` | Named records the labelled dataset refers to (e.g. `return_window_day_30`, `late_and_double_charged`, `not_owner`, `several_recent_orders`). |

## Order statuses

`placed`, `packed`, `shipped`, `in_transit`, `out_for_delivery`, `delivered`, `cancelled`,
`return_in_progress`, `returned`, `refunded`. "Delayed" (past `promised_delivery_date`)
and "lost" (last tracking event older than `policy.delivery.lost_after_days_without_update`)
are derived by router code, not stored (D-011).

## Coverage (SD-1 to SD-5)

- VIP customers, customers with several registered emails, customers with contact history.
- Every status, plus delayed and lost in-transit orders, including the 6- and 7-day lost
  boundary.
- Deliveries 29, 30 and 31 days ago (return window), and 6, 7 and 8 days ago (damage window).
- Non-returnable items, orders above the 50,000 high-value threshold (and one just below),
  multi-item orders, a partially returned order, and two orders placed the same day
  (one delivered, one late).
- Duplicate charges, a failed-then-retried payment, a failed unpaid order, and refunded orders.
- Identity cases: a secondary-email sender, one recent order, several recent orders, a
  customer with no orders, and an unknown sender.
